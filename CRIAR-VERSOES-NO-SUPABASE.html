Criar as tabelas de versão

Segunda e última vez que você precisa colar comando. Depois é duplo clique.

O que este comando faz — e o que ele NÃO faz.
  • Cria duas tabelas: uma com a identidade de cada motor (qual versão, quando, o que mudou) e outra com a impressão digital de cada arquivo que compõe cada um.
  • Não apaga nada. Não altera nenhuma linha de pontuação. Não toca no molde. As versões 2 e 3 do molde continuam onde estão — são histórico.

O passo a passo

  1. Abra o editor: supabase.com → SQL Editor
  2. Clique no botão verde — o comando vai para a área de transferência.
  3. Clique dentro do editor, Ctrl+A e depois Ctrl+V.
  4. Ctrl+Enter para rodar.
  5. Se pedir confirmação, pode confirmar — ela sempre aparece quando o comando cria tabela.
  6. Deve aparecer Success. No rows returned.
  7. Volte para a pasta e dê dois cliques no SUBIR-VERSOES.bat.

O comando

-- ============================================================
--  AS VERSOES DO MOLDE E DOS MOTORES  ·  16/08/2026
--  So acrescenta. Nao apaga nada, nao toca no molde nem nas pontuações.
-- ============================================================

-- 1) A identidade de cada motor.
create table if not exists motor_versao (
  motor          text        not null,   -- 'otimizacao' | 'bonus'
  versao         int         not null,
  quando         date,
  o_que_mudou    text,
  vigente        boolean     not null default false,
  atualizado_em  timestamptz not null default now(),
  primary key (motor, versao)
);

comment on table motor_versao is
  'Qual versao de cada motor existe, quando entrou e o que mudou nela. Ordem do Luis 16/08: "tem que deixar registrado as versoes desses motores".';

-- 2) A impressao digital de cada arquivo que compoe cada motor.
--    E ela que permite provar, um mes depois, que duas pontuações sairam da MESMA receita.
create table if not exists motor_arquivo (
  motor          text        not null,
  versao         int         not null,
  arquivo        text        not null,
  bytes          bigint,
  md5            text,
  modificado_em  timestamptz,
  atualizado_em  timestamptz not null default now(),
  primary key (motor, versao, arquivo)
);

comment on table motor_arquivo is
  'A impressao digital (md5) de cada arquivo que compoe um motor. Serve para a trava: antes de rodar, SUBIR-VERSOES.bat conferir compara o que esta na pasta com o que esta gravado aqui, e avisa se a receita mudou.';

create index if not exists motor_arquivo_md5_idx on motor_arquivo (md5);

-- 3) Uma visao que responde de cara: o banco guarda o molde que ele diz que vale?
create or replace view molde_confere as
select v.versao,
       v.nome,
       v.vigente,
       (select count(*) from molde m where m.versao = v.versao)              as linhas_no_banco,
       (select count(distinct m.funcao) from molde m where m.versao = v.versao) as funcoes_no_banco
from molde_versao v
order by v.versao;

comment on view molde_confere is
  'Linha a linha: o que a molde_versao DECLARA contra o que a tabela molde REALMENTE tem. Em 16/08 a v5 estava declarada vigente com ZERO linhas gravadas.';
A conta que motivou isto.
Em 16/08 o banco declarava a versão 5 como vigente e guardava só as versões 2 e 3 — 468 linhas cada, que é o desenho de 18 funções. O molde 5 tem 494 itens e 19 funções. Estava assim desde 12/08, e qualquer conferência feita pelo banco dava resposta errada sem avisar.
