A troca da chave — passo 1 de 3

Este é o único passo perigoso da reforma. Por isso ele foi partido em três, e este primeiro não tira nada.

1. ACRESCENTAR Cria a coluna do código do lado do nome e enche. Você está aqui. Nada é apagado, nada muda de valor. Se der errado, apaga a coluna e acabou.
2. PROVAR Rodar dias com as duas juntas e conferir que dizem a mesma coisa, sempre.
3. TROCAR Só então a chave estrangeira passa a apontar para o código. Aí sim tem risco — e só com você olhando.
⛔ Por que tanta cerimônia para trocar uma chave
As três tabelas apontam para funcoes.nome com apagamento em cascata. Se o nome sumir da tabela funcoes, o banco apaga sozinho, sem perguntar: 
builds        11.133 linhas de resultado   (horas de motor)
molde          1.430 linhas               (o alvo de cada atributo)
estilo_valor     144 linhas
E o nome muda: mudou oito vezes só nesta semana. Ponta finalizadora virou Atacante finalizador. Enquanto a chave for o nome, renomear uma função é apagar resultado.

Se rodar duas vezes, a segunda não faz nada de novo.

O passo a passo

  1. Abra o editor: supabase.com → SQL Editor
  2. Clique no botão verde.
  3. No editor: Ctrl+A, Ctrl+V, Ctrl+Enter.
  4. Ele termina mostrando uma tabela de conferência. Me mande a foto dela.
O que a tabela de conferência tem de dizer 
tabela          linhas   com codigo   SEM codigo
builds          11.133       11.133            0
molde            1.430        1.430            0
estilo_valor       144          144            0
A coluna da direita tem de ser zero nas três. Se não for, tem nome na tabela que não existe mais em funcoes — e aí a lista aparece logo abaixo, com o nome e quantas linhas. Nesse caso não siga para o passo 2. Me mande a lista. 

-- ============================================================
--  A TROCA DA CHAVE — PASSO 1 de 3: ACRESCENTAR
--  16/08/2026
--
--  ⛔ Este comando NAO apaga nada, NAO muda valor nenhum e NAO
--     toca em chave estrangeira. So acrescenta uma coluna e
--     enche ela. Rodar duas vezes nao faz mal.
-- ============================================================

-- 1) A coluna do codigo, ao lado do nome, nas tres tabelas.
do $$
declare
  t text;
  col text;
begin
  foreach t in array array['builds','molde','estilo_valor'] loop
    -- descobre como a tabela chama a coluna da funcao (funcao ou funcao_nome)
    select column_name into col
      from information_schema.columns
     where table_schema = 'public' and table_name = t
       and column_name in ('funcao','funcao_nome','nome_funcao')
     limit 1;

    if col is null then
      raise notice 'tabela % nao tem coluna de funcao — pulei', t;
      continue;
    end if;

    execute format('alter table %I add column if not exists funcao_codigo text', t);

    execute format(
      'update %I x set funcao_codigo = f.codigo
         from funcoes f
        where f.nome = x.%I
          and f.codigo is not null
          and x.funcao_codigo is distinct from f.codigo', t, col);

    raise notice 'tabela % : coluna % -> funcao_codigo preenchida', t, col;
  end loop;
end $$;

comment on column builds.funcao_codigo is
  'O codigo fixo da funcao, ao lado do nome. 16/08: PASSO 1 da troca da chave — a coluna existe e esta cheia, mas a chave estrangeira AINDA aponta para o nome. Nada depende desta coluna ainda.';

-- 2) A visao de conferencia. E ela que diz se pode seguir.
create or replace view chave_a_trocar as
select 'builds'       as tabela, count(*) as linhas,
       count(funcao_codigo) as com_codigo,
       count(*) - count(funcao_codigo) as sem_codigo from builds
union all
select 'molde',        count(*), count(funcao_codigo), count(*) - count(funcao_codigo) from molde
union all
select 'estilo_valor', count(*), count(funcao_codigo), count(*) - count(funcao_codigo) from estilo_valor;

comment on view chave_a_trocar is
  'Quantas linhas de cada tabela ja tem o codigo da funcao ao lado do nome. Enquanto sem_codigo nao for ZERO nas tres, a troca da chave NAO PODE acontecer.';

-- 3) A visao dos nomes que nao casaram — a lista do que impede seguir.
create or replace view chave_sem_par as
select 'builds' as tabela, funcao as nome_que_nao_casou, count(*) as linhas
  from builds where funcao_codigo is null group by 1,2
union all
select 'molde', funcao, count(*) from molde where funcao_codigo is null group by 1,2
union all
select 'estilo_valor', funcao, count(*) from estilo_valor where funcao_codigo is null group by 1,2
order by linhas desc;

comment on view chave_sem_par is
  'Os nomes de funcao que existem nas tabelas de resultado mas NAO existem mais na tabela funcoes. Cada um destes e um nome que ficou para tras num renomeio. Enquanto houver linha aqui, a chave nao se troca.';

-- ============================================================
--  A CONFERENCIA — e isto que tem de aparecer na tela
-- ============================================================
select * from chave_a_trocar;
Depois que a conferência der zero nos três
Não faça mais nada hoje. O passo 2 é deixar rodando — o motor continua escrevendo pelo nome, a coluna do código continua sendo preenchida, e a gente confere de tempos em tempos que as duas dizem a mesma coisa. Só depois disso a chave muda.

Enquanto isso, nada no sistema depende da coluna nova. Ela é só uma testemunha.
